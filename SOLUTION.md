Серверная пагинация не реализована, поскольку предоставленный API возвращает весь список одним JSON-файлом.

## Решения

Фильтрация. В Предстоящие попадают `scheduled`, в Завершённые — `finished`. Статусы `live` и `postponed` отображаются в Все, поскольку они не относятся однозначно к двум другим категориям.

Нестандартные данные. Счёт `0:0` отображается корректно, `score: null` заменяется прочерком, а при `startsAt: null` выводится Дата уточняется. Время форматируется в часовом поясе устройства. Статус берётся из ответа API, а не вычисляется по текущей дате.

Обновление данных. Выбран polling раз в 30 секунд: для небольшого списка это простой способ поддерживать данные актуальными. Параллельные запросы блокируются, при неактивной вкладке polling приостанавливается, а при ошибке предыдущие данные сохраняются. Время последнего обновления меняется только после успешной загрузки.

Производительность. `FlatList` ограничивает количество одновременно отображаемых элементов. При обновлении неизменённые объекты матчей сохраняют прежние ссылки, чтобы уменьшить лишние перерисовки.

## Баги из части 2

1. Звёздочки: `Boolean(favorites.indexOf(id))` возвращал неправильный результат, поскольку `Boolean(-1) === true`. Дополнительно массив изменялся напрямую через `push` и `splice`, из-за чего React мог не перерисовывать компонент. Исправлено через `includes()` и функциональное обновление состояния с созданием нового массива.

2. Обновлено N сек назад: обработчик `setInterval` захватывал устаревшее значение `seconds` из замыкания, поэтому счётчик застывал. Также интервал не очищался и не реагировал на изменение `since`. Теперь разница вычисляется относительно текущего времени, а эффект пересоздаётся при изменении даты последней успешной загрузки и очищает таймер.
